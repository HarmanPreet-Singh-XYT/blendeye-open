# Taste
- Gives short, high-level directives ("research X", "implement it", "fill the gap") and expects the agent to explore the codebase, resolve the referent itself, and make implementation decisions autonomously rather than being walked through step by step. Confidence: 0.55
- Verifies completion skeptically ("is everything done?"), so wants an explicit split between what was actually verified (tests/builds run, dangling references checked) and what was assumed or left untested. Confidence: 0.4
- Likes the agent to close out with a short menu of concrete proposed next steps, then picks from it by reference ("can you do the 3rd and 4th point") instead of restating the task. Confidence: 0.4
- When swapping a third-party dependency/model/API for a replacement, wants a complete migration: adopt the new provider's full capability set and remove features it doesn't support rather than stubbing or faking them. Confidence: 0.5
- When flagging a correctness/robustness risk, expects the fix applied exhaustively across every analogous case, not just the reported one (e.g. "make sure that for other supabase objects too"), preferring a central guard enforced at all boundaries rather than a narrow local patch. Confidence: 0.55
- Uses `uv` for Python environment and command execution (e.g. `uv sync`, `uv run uvicorn ...`) and expects run/install instructions given in `uv` terms rather than raw pip/venv. Confidence: 0.6
- Treats each new repo/project as fully separate from existing ones: when a workflow or deployment was copied from a service that already exists, expects identifiers (deployed service name, workflow filename, display name) renamed/namespaced to the new repo so the existing service is never targeted or overwritten. Confidence: 0.55
- Wants doc-derived or stub-tested integrations actually exercised against the real service ("fill the gap" = run a live end-to-end smoke test) rather than left as statically-verified code, and is willing to spend real/billable API calls to confirm untested paths. Confidence: 0.45
